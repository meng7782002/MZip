# 压缩解压工具 技术方案设计

- 版本：v1.1（在 v1.0 基础上修正日志配置、参数传递与界面细节描述）
- 日期：2026-11-02 09:34
- 项目：QuickZip（WPF / .NET 8）

## 1. 总体架构

```
QuickZip (WPF .NET 8)
 ├─ MainWindow.xaml / MainWindow.xaml.cs   界面与事件（无 MVVM，直接代码后置）
 ├─ Dialogs/                               创建压缩包、密码、覆盖策略、设置、关于对话框
 ├─ Models/ArchiveItem.cs                  压缩包条目实体
 ├─ Services/SevenZipEngine.cs             7-Zip 命令行封装（列表/解压/压缩/追加/删除/测试）
 ├─ Services/ProcessRunner.cs              进程执行、stdout 解析、进度回调、取消
 ├─ Services/SettingsService.cs            config/settings.json 读写
 ├─ Services/LogHelper.cs                  log4net 初始化与封装（程序化配置）
 └─ tools/7z.exe + 7z.dll                  内置 7-Zip 引擎（LGPL）
```

不使用接口、不使用 MVVM、不使用依赖注入，全部为普通实体类与静态/实例方法，便于调试。

## 2. 压缩引擎选型

| 方案 | 结论 |
| --- | --- |
| SharpCompress（MIT） | 可读写 ZIP，可读 7Z/RAR，但 **不能写 7Z**，RAR5 支持不完整 |
| 7-Zip 官方命令行（LGPL + unRAR 限制） | 列表/解压/压缩/测试/删除全格式覆盖，RAR5 与 AES 加密支持完善，可商用免费 |

最终采用 **内置 7-Zip 26.05 x64**（`tools/7z.exe`、`tools/7z.dll`），通过 `ProcessStartInfo.ArgumentList` 逐项传参（不拼接命令行字符串），避免空格、中文与引号转义问题。统一使用的参数：

- `-sccUTF-8`：控制台输出 UTF-8，避免中文乱码
- `-slt`：详细列表输出，便于逐条解析
- `-bsp1 -bb1`：进度百分比与当前处理文件输出到 stdout
- `-p密码`：始终显式传入（无密码时传 `-p`），并关闭标准输入，避免 7-Zip 交互等待密码导致进程挂起
- 覆盖策略：覆盖 → `-y`；跳过已有 → `-aos -y`；自动重命名 → `-aou -y`

### 关键命令

| 功能 | 命令 |
| --- | --- |
| 列表 | `7z l -slt -sccUTF-8 -p密码 压缩包` |
| 解压全部 | `7z x -o输出目录 -y -bsp1 -bb1 -sccUTF-8 -p密码 压缩包` |
| 解压选中 | `7z x -o输出目录 -y -bsp1 -bb1 -sccUTF-8 -p密码 压缩包 条目1 条目2 ...` |
| 创建 | `7z a -t7z\|-tzip -mx=N -bsp1 -bb1 -sccUTF-8 [-p密码 [-mhe=on|-mem=AES256]] 目标 来源1 来源2 ...` |
| 追加 | `7z a -mx=N -bsp1 -bb1 -sccUTF-8 -p密码 压缩包 来源1 来源2 ...` |
| 删除 | `7z d -y -p密码 压缩包 条目1 条目2 ...` |
| 测试 | `7z t -bsp1 -sccUTF-8 -p密码 压缩包` |

来源路径直接作为参数传入（绝对路径由 7-Zip 自动剥离公共父目录并保留顶层名称）。当累计参数长度超过 30000 字符时，应用层直接提示分批处理，避免触碰 Windows 命令行长度上限。

## 3. 进度与取消

- `ProcessRunner` 异步读取 stdout/stderr，按 `\r`/`\n` 分段回调，正则匹配 `(\d+)%` 更新进度。
- 解压/压缩回调 `Action<OperationProgress>`（百分比、阶段、当前条目）。
- 取消：`process.Kill(entireProcessTree: true)`，取消后清理未完成的输出文件并复位 UI。
- stdout/stderr 全部写入日志（DEBUG 级别），失败时输出完整 7-Zip 信息。

## 4. 列表解析

`7z l -slt` 输出为 `键 = 值` 的块结构，块之间以 `----------` 分隔。解析规则：

- 首个块为压缩包自身信息（`Path = 压缩包路径`），作为汇总信息。
- 后续块以 `Path =` 开始，读取 `Folder`、`Size`、`Packed Size`、`Modified`、`Attributes`、`CRC`、`Encrypted` 字段。
- 目录条目（`Folder = +`）在界面上以文件夹图标展示，不参与大小统计。
- 日期字符串格式 `yyyy-MM-dd HH:mm:ss` 直接解析，解析失败则置空。
- 加密条目在名称后显示橙色“加密”文字徽章。

## 5. 界面设计

- 顶部菜单：文件（打开/最近打开/新建/退出）、操作（解压/添加/删除/测试/刷新/关闭）、工具（设置/关于）。
- 顶部工具栏：打开、解压全部、解压选中、新建、添加、删除、测试、刷新、设置、关于。
- 压缩包信息卡片：名称、完整路径、格式、文件数、目录数、原始大小、压缩后、压缩率。
- 条目 DataGrid：名称（显示条目完整路径，文件夹/文件使用矢量图标）、大小、压缩后、压缩率、修改时间、CRC、属性；数值列正文与列头右对齐。
- 底部状态栏：状态文本 + 操作进度条 + 百分比 + 取消按钮；空闲时隐藏进度条与百分比。
- 视觉：浅色主题，强调色 #2F6FED，圆角卡片，Segoe MDL2 图标（锁/警告等使用系统图标，文件夹与文件使用 XAML 矢量图形）。
- 拖拽：窗口整体接受文件拖放；空状态下拖入压缩包即打开，已打开压缩包时拖入文件作为“添加”源。
- 用户偏好：仅展示必要信息，不放置多余装饰；控件位置固定。

## 6. 日志

- log4net 3.5.0，采用**程序化配置**（`LogHelper.Initialize()`），不依赖外部 `log4net.config` 文件。
- 输出：`logs/quickzip<yyyy-MM-dd>.log`，按天滚动，`MaxSizeRollBackups = 30`。
- 级别：INFO（启动、打开、操作开始/完成）、DEBUG（7-Zip 原始输出）、WARN、ERROR（异常堆栈）。
- 未捕获异常（UI 线程 `DispatcherUnhandledException`、后台任务 `TaskScheduler.UnobservedTaskException`）统一记录。
- 日志初始化失败不阻断程序运行。

## 9. 异常与边界处理

- 找不到 `7z.exe`：提示“压缩引擎缺失”，并记录日志。
- 密码错误：7-Zip 返回码 2 且输出包含 `Wrong password` / `Cannot open encrypted archive`，转为中文提示；打开与解压时均可重新输入密码（循环重试，直到成功或取消）。
- 条目名包含非法字符/路径穿越（`..`）：解压时由 7-Zip 处理，应用层仅按 7-Zip 结果提示。
- 取消：返回码非 0 但标记为用户取消，不弹错误。
- 文件被占用：提示“文件正在被其他程序使用”。
- 保存路径位于被压缩文件夹内部：创建对话框阻止并给出提示，避免自我包含。

## 10. 验证方式

1. 引擎集成测试（临时控制台工程）：RAR4/RAR5 列表与解压、ZIP 中文名与密码创建、错误密码识别、7Z 加密头无密码不阻塞、追加/删除、完整性校验、选中解压、跳过覆盖、进度回调，共 13 项全部通过。
2. 运行程序创建 ZIP/7Z（含中文名、AES-256 加密），再用 7-Zip 校验。
3. 用 RAR/RAR5 样本验证只读解压与界面展示。
4. 通过 `PrintWindow` 截图检查空状态、已打开压缩包、加密徽章、列头对齐等界面细节。
5. 检查日志文件、取消与异常场景。
